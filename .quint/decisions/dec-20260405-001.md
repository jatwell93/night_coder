# Ralph Orchestrator (hat-based fresh-context loop)

## 1. Problem Frame

**Signal:** Ten orchestration candidates researched; need to select one tool to run an autonomous coding agent loop overnight on a budget VPS. Choice shapes runbook, trace format, and pillar integration patterns. Wrong pick wastes the pilot weekend and creates rework.

**Constraints:**
- Total monthly spend <$150 AUD (VPS + LLM combined)
- No OpenAI provider dependency (Anthropic, Google, DeepSeek, GLM, OpenRouter all acceptable)
- Must run headless/unattended for up to 10h on a VPS
- Must be BYO-API-key model — no mandatory commercial CLI subscription (Claude Max, Cursor Pro, etc.)
- Must not prevent integration with external Judge, DTU, Leash, and Observability pillars
- Framework/orchestrator itself must be free/OSS

## 2. Decision

**Selected:** Ralph Orchestrator (hat-based fresh-context loop)

Ralph wins on the three pilot-critical axes: (1) Resource footprint — <500MB vs OpenHands 1.5-2.5GB, leaving 3x more headroom on a budget VPS for the actual coding work + Mockoon container. (2) Native safety limits — max_cost_usd, max_iterations, max_runtime_seconds are built-in, essential for a $10 pilot budget cap without external wrappers. (3) Context drain resistance — fresh-per-cycle philosophy directly addresses the user stated concern about long-run context degradation. Additionally, per-hat model routing allows budget optimization (expensive models for complex tasks, cheap for simple). File-based architecture (.agent/events.jsonl + scratchpad.md) produces traces parseable by the external Python judge without SDK dependencies. The simplicity of disk-is-state, git-is-memory fits a solo operator who does not want to debug a complex orchestrator on Friday night.

**Invariants:**
- Orchestrator must never require a commercial CLI subscription to function
- Orchestrator must have a documented headless/non-interactive execution path
- All trace output must be file-based and parseable without proprietary SDK
- Safety limits (cost, time, iterations) must be enforceable before the run starts
- Orchestrator must not prevent integration with external Judge, DTU, Leash, Observability pillars

**Pre-conditions:**
- [ ] Ralph installed and quick-start verified on target VPS
- [ ] At least one hat configured with a non-OpenAI model backend (Anthropic API, DeepSeek, OpenRouter)
- [ ] max_cost_usd, max_iterations, max_runtime_seconds set in config matching CONSTRAINTS.md
- [ ] Mockoon DTU container running and verified (curl test passes)
- [ ] Pilot repo cloned on VPS with sandbox-app/ping_upstream.py starter in place

**Post-conditions:**
- [ ] Overnight run produces .agent/events.jsonl with reviewable trace entries
- [ ] Git log shows at least one agent commit on pilot branch
- [ ] No spend exceeds $10 AUD for the pilot run
- [ ] Morning review can be completed by reading events.jsonl + git diff without re-running anything

**Admissibility:**
- NOT: Must not use OpenAI as model provider
- NOT: Must not require interactive approval during overnight window
- NOT: Must not exceed $150 AUD/month total (VPS + LLM) in steady state
- NOT: Must not require Claude Code Max subscription

**Weakest link:** Single-agent sequential execution and manual crash recovery. If the run dies at hour 3 of 10, you lose the remaining 7 hours and must manually restart. For a pilot this is acceptable (partial traces are still learning). For v2 production, this becomes the binding constraint driving migration to OpenHands or similar.

**Evidence requirements:**
- Successful headless run on VPS producing git commits and trace files
- Actual LLM spend for pilot run measured and under $10 AUD
- events.jsonl trace readable and parseable by external Python judge
- Resource usage (RAM, CPU) on VPS during 10h run stays within VPS limits

## 4. Consequences

**Rollback plan:**
Triggers:
- Ralph fails to produce usable traces on first pilot attempt
- Resource usage exceeds VPS capacity during pilot
- Per-hat model routing does not support required providers
- Time-to-configure exceeds 4 hours on pilot day
Steps:
1. Switch to OpenHands headless (pre-tested fallback per vertical slice plan)
2. Update DECISIONS.md Orchestration row to OpenHands
3. Adjust runbook PILOT-WEEKEND.md detach block to openhands --headless command
4. Re-run pilot on next available overnight window
Blast radius: Pilot branch only — no production impact. Runbook and trace format change but external pillars (Judge, DTU, Leash, Observability) are designed to be orchestrator-agnostic.

**Refresh triggers:**
- Re-evaluate if VPS budget increases to allow 16GB+ RAM (OpenHands footprint concern disappears)
- Re-evaluate if Ralph project becomes unmaintained (check GitHub activity quarterly)
- Re-evaluate if Anthropic opens Claude Code CLI for API-only access (Ruflo re-enters)
- Re-evaluate after pilot retrospective — actual evidence may shift the comparison
- Re-evaluate when scaling beyond single-scenario pilot to multi-repo overnight runs
