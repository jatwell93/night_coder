# Doppler (service tokens + doppler run) as Secrets/IAM pillar

## 1. Problem Frame

**Signal:** Provider API keys and bootstrap credentials must not live in repo or plain CI YAML; rotation and least-privilege boundaries are undefined for the pilot.

**Constraints:**
- Headless CI and overnight runners
- Solo-operator manageable ops
- User preference to evaluate Doppler seriously
- Secrets must not leak into Langfuse traces or git by default

**Acceptance:** One documented pattern: how the agent and CI obtain keys; one service token or equivalent per trust boundary; redaction rules stated.

## 2. Decision

**Selected:** Doppler (service tokens + doppler run) as Secrets/IAM pillar

Minimizes bootstrap secrets in CI, matches overnight agent ergonomics, and provides a credible path to rotation and integration sync without operating Vault or Lambda rotation in the pilot.

**Invariants:**
- Only Doppler service tokens (read-only, per config) in CI as long-lived bootstrap
- Agent and judge processes started under doppler run or equivalent injection
- No API keys committed; redact secrets in logs and Langfuse payloads by policy

**Pre-conditions:**
- [ ] Doppler project with pilot and ci configs
- [ ] Service tokens created per trust boundary

**Post-conditions:**
- [ ] Documented env var names and doppler run entrypoints
- [ ] Redaction checklist for traces

**Admissibility:**
- NOT: Storing raw provider keys in GitHub Actions yaml or repo files
- NOT: Sharing one mega-token across unrelated projects

## 3. Rationale

| Variant | Verdict | Reason |
|---------|---------|--------|
| Doppler (service tokens + doppler run) as Secrets/IAM pillar | **Selected** | Minimizes bootstrap secrets in CI, matches overnight agen... |
| 1Password CLI + Connect or service account | Rejected | Admissible when org already standardizes on 1Password; otherwise extra moving parts vs Doppler for greenfield. |
| SOPS + age in repo | Rejected | Good for static encrypted config; weaker for dynamic fetch and rotation of many provider keys without extra tooling. |

**Weakest link:** Vendor availability and operator discipline on trace/log redaction.

**Evidence requirements:**
- Dry-run: CI job proves keys never echo in logs
- Token scoped to single config verified in dashboard

## 4. Consequences

**Rollback plan:**
Triggers:
- Doppler outage blocks critical run
Steps:
1. Rotate to static GitHub encrypted secrets per provider
2. Remove Doppler CLI from entrypoints

**Refresh triggers:**
- Corporate mandate for 1Password or Vault
- Multi-cloud dynamic secrets required
