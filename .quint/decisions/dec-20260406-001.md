# Ralph Orchestrator (hat-based fresh-context loop)

## 1. Problem Frame

**Signal:** Ten orchestration candidates have been researched across the Attractor pillar (OpenHands, AG2, Deer Flow, CrewAI, AgentFlow, Gas Town, oh-my-openagent, Ralph, Ruflo, Agent Flywheel). We need to select one tool to serve as the orchestration spine for an autonomous overnight coding loop on a budget VPS. The choice constrains runbook format, trace output, pillar integration patterns (Judge, DTU, Leash, Observability), and cost profile. A wrong pick wastes the pilot weekend and creates downstream rework across all five pillars.

**Constraints:**
- Total monthly spend <$150 AUD (VPS + LLM combined)
- No OpenAI-only provider lock-in — must support Anthropic, Google, DeepSeek, or OpenRouter
- Must run headless/unattended for up to 10 hours on a single budget VPS (e.g. Hetzner CX22, 4GB RAM)
- Must be BYO-API-key — no mandatory commercial CLI subscription (Claude Max, Cursor Pro, etc.)
- Must not prevent integration with external Judge, DTU, Leash, and Observability pillars
- Framework/orchestrator itself must be free/OSS (MIT, Apache-2, etc.)
- Must produce file-based traces readable without proprietary SDKs for morning human review

**Acceptance:** A single orchestrator is selected with documented rationale. Decision includes rollback plan (fallback orchestrator identified), refresh triggers, and evidence requirements for post-pilot measurement.

## 2. Decision

**Selected:** Ralph Orchestrator (hat-based fresh-context loop)

Ralph wins on the three pilot-critical axes derived from our constraints and optimization targets: (1) Resource footprint — <500MB vs OpenHands' 1.5-2.5GB, leaving 3x more headroom on a 4GB VPS for Mockoon container + actual coding agent work. A 10h run on a tight VPS cannot afford OOM risk. (2) Native safety limits — max_cost_usd, max_iterations, max_runtime_seconds are built into the config, essential for enforcing a $10 AUD pilot budget without building external wrapper scripts on Friday night. (3) Context drain resistance — fresh-per-cycle philosophy directly addresses long-run context degradation, which is the highest-risk failure mode for a 10h unattended run. Additionally: per-hat model routing enables budget optimization (expensive model for complex reasoning, cheap model for simple edits); file-based architecture (.agent/events.jsonl + scratchpad.md) produces traces parseable by the external Python judge without any SDK dependency; the disk-is-state, git-is-memory architecture means a solo operator doesn't need to debug container orchestration on Friday night.

**Invariants:**
- Orchestrator must never require a commercial CLI subscription to function (BYO API key only)
- Orchestrator must have a documented headless/non-interactive execution path
- All trace output must be file-based and parseable without proprietary SDK
- Safety limits (cost, time, iterations) must be enforceable before the run starts, not added retroactively
- Orchestrator must not prevent integration with external Judge, DTU, Leash, and Observability pillars
- Pilot work stays on a disposable branch — no merging without human sign-off

**Pre-conditions:**
- [ ] Ralph installed and quick-start verified on target VPS or local machine
- [ ] At least one hat configured with a non-OpenAI model backend (Anthropic API, DeepSeek, or OpenRouter)
- [ ] max_cost_usd, max_iterations, max_runtime_seconds set in config matching CONSTRAINTS.md ($10 AUD cap)
- [ ] Mockoon DTU container running and verified (curl http://127.0.0.1:3000/api/status returns ok)
- [ ] Pilot repo cloned on target with sandbox-app/ping_upstream.py starter in place
- [ ] PROMPT.md created with task description for Ralph to execute

**Post-conditions:**
- [ ] Overnight run produces .agent/events.jsonl with reviewable trace entries
- [ ] Git log shows at least one agent commit on pilot branch
- [ ] No spend exceeds $10 AUD for the pilot run
- [ ] Morning review can be completed by reading events.jsonl + git diff without re-running anything
- [ ] Judge (pilot_judge.py) can parse traces and produce verdict JSON

**Admissibility:**
- NOT: Must not use OpenAI as the sole model provider
- NOT: Must not require interactive approval during overnight window
- NOT: Must not exceed $150 AUD/month total (VPS + LLM) in steady state
- NOT: Must not require Claude Code Max or any commercial CLI subscription
- NOT: Must not silently continue after hitting cost/time/iteration limits

## 3. Rationale

| Variant | Verdict | Reason |
|---------|---------|--------|
| Ralph Orchestrator (hat-based fresh-context loop) | **Selected** | Ralph wins on the three pilot-critical axes derived from ... |
| V1. OpenHands | Rejected | Non-dominated — stays as v2 fallback and upgrade path. Wins on crash recovery (event-sourced replay), trace richness (structured JSONL), and model breadth (LiteLLM 100+ providers). But Docker-in-Docker consumes 1.5-2.5GB on a 4GB VPS where total budget constrains size. No native cost cap means pilot budget enforcement is fragile. For the pilot (learning goal, not production SLA), Ralph's lighter profile fits better. OpenHands becomes the natural upgrade when scaling beyond one scenario, needing parallelism, or moving to a larger VPS. |
| V3. CrewAI | Rejected | Dominated on time-to-first-run (days not hours) and assembly_required (build overnight supervision layer yourself). Third-party reports of unstable long loops. Role-based model is excellent conceptually for v2 multi-agent expansion but premature for a single-scenario pilot. Stepping stone value preserved: CrewAI patterns can layer on any orchestrator later. |
| V4. AG2/AutoGen | Rejected | Dominated on assembly_required (build-significant-pieces — no standalone headless runner, you build the entire overnight harness). Time-to-first-run is days. No native safety limits. Accumulates-forever context model is worst in field. LangGraph adds checkpointing but also adds LangChain dependency complexity. |
| V5. Deer Flow | Rejected | Dominated on time-to-first-run (days, no documented headless path) and native_safety_limits (none). Parallel sub-agents are valuable but wasted on single-scenario pilot. Persistence story is 'memory file + DB suggestion', not production checkpoint system. |
| V6. AgentFlow (Stanford) | Rejected | Categorically different — research contribution (training methodology + paper), not an operational tool. No CLI, no deployment path, no traces, no safety limits. Eliminated at classification stage, not at comparison stage. |
| V7. Gas Town | Rejected | Constraint violation: single-provider-locked to Claude Code CLI (Anthropic only). Cost tracking broken (issue #24). Anecdotal $200/month for 10h exceeds budget. Parallelism value prop wasted on single-scenario pilot. Strong philosophical alignment with StrongDM Attractor but constraint violation is disqualifying. |
| V8. oh-my-openagent | Rejected | Dominated by Ralph on every operational dimension. Best conceptual phase model (Sisyphus/Prometheus/Atlas) but maturity gaps (dev branch default, naming migration, breaking configs, ephemeral /tmp debug log) mean you risk debugging the orchestrator instead of testing the overnight flow. Phase architecture ideas worth studying regardless. |
| V9. Ruflo/claude-flow | Rejected | Constraint violation: hard dependency on Claude Code CLI (Anthropic only). User has Claude Code Pro (not Max) which runs out quickly. Smart 3-tier routing genuinely reduces cost but doesn't eliminate dependency. v3 alpha stability compounds risk. If Anthropic stabilizes CLI access and user upgrades to Max, Ruflo re-enters consideration. |
| V10. Agent Flywheel/ACFS | Rejected | Not a standalone orchestrator — coordination layer (NTM + MCP mail) over other agent CLIs. Still requires underlying coding agent subscription. NTM's policy YAML and audit are strong Leash/CXDB value but don't replace the orchestration spine. NTM could complement Ralph or OpenHands as Leash layer. |

**Weakest link:** Single-agent sequential execution and manual crash recovery. If the run dies at hour 3 of 10, the remaining 7 hours are lost and manual restart is required. For the pilot this is acceptable (partial traces are still valuable learning). For v2 production, this becomes the binding constraint driving migration to OpenHands or a multi-agent orchestrator.

**Evidence requirements:**
- Successful headless run on VPS or local machine producing git commits and .agent/events.jsonl trace
- Actual LLM spend for pilot run measured and confirmed under $10 AUD
- events.jsonl trace readable and parseable by external Python judge (pilot_judge.py)
- Resource usage (RAM, CPU) during 10h run stays within VPS limits (4GB RAM)
- Time-to-configure measured: from git clone to first successful hat execution

## 4. Consequences

**Rollback plan:**
Triggers:
- Ralph fails to produce usable traces on first pilot attempt
- Resource usage exceeds VPS capacity (OOM, swap thrashing) during pilot
- Per-hat model routing does not support required providers (Anthropic, DeepSeek, OpenRouter)
- Time-to-configure exceeds 4 hours on pilot day
- Ralph project becomes unmaintained (no commits or issue responses for 60+ days)
Steps:
1. Switch to OpenHands headless (V1, pre-identified fallback from Pareto front)
2. Update DECISIONS.md Orchestration row to OpenHands
3. Adjust runbook PILOT-WEEKEND.md detach block to: timeout 10h openhands --headless --json -f task.txt
4. Re-run pilot on next available overnight window
5. If OpenHands also fails, fall back to bare tmux + API script approach
Blast radius: Pilot branch only — no production impact. Runbook and trace format change but external pillars (Judge, DTU, Leash, Observability) are designed to be orchestrator-agnostic per the architecture.

**Refresh triggers:**
- Re-evaluate if VPS budget increases to allow 16GB+ RAM (OpenHands footprint concern disappears)
- Re-evaluate if Ralph project becomes unmaintained (check GitHub activity quarterly)
- Re-evaluate if Anthropic opens Claude Code CLI for API-only access without Max subscription (Ruflo and Gas Town re-enter)
- Re-evaluate after pilot retrospective — actual measured evidence may shift the comparison
- Re-evaluate when scaling beyond single-scenario pilot to multi-repo overnight runs (parallelism becomes a real target, not observation)
