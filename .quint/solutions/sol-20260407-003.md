# Solutions for: Artifact registry pillar for overnight pilot

Problem: prob-20260407-003

## Variants (3)

### V1. Git + run manifest conventions

runs/<date>/<id>/ with manifest.json, plan.md, verdict.md, summary.json; large blobs as DVC or S3 URIs only.

**Strengths:**
- Zero new services
- Review-friendly
- SHA reproducibility

**Weakest link:** Ad hoc querying across many runs without SQL

**Risks:**
- Repo size if discipline slips

**Stepping stone:** yes — opens future possibilities

**Rollback:** Flatten to single artifacts dir

### V2. SQLite catalog + object pointers

Embedded DB rows for runs and artifact URIs; blobs external.

**Strengths:**
- SQL filters
- Still lightweight

**Weakest link:** Single-writer and backup discipline

**Risks:**
- Migration if schema evolves

**Stepping stone:** yes — opens future possibilities

**Rollback:** Drop DB; keep git manifests

### V3. MLflow-style tracking server

Full experiment server + artifact store analogous to ML training platforms.

**Strengths:**
- Mature UI patterns

**Weakest link:** Heavy ops for solo pilot; overlap with Langfuse for traces

**Risks:**
- Duplicate observability confusion

**Rollback:** Shut down server

## Summary
