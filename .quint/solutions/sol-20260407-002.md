# Solutions for: Secrets and IAM pillar for overnight autonomous coding

Problem: prob-20260407-002

## Variants (3)

### V1. Doppler (service tokens + doppler run)

Central project/config; read-only service token per trust boundary; CI stores only DOPPLER_TOKEN; agents started via doppler run; path to rotation and GitHub sync for v1.

**Strengths:**
- Single bootstrap secret
- Strong agent ergonomics
- Rotation story

**Weakest link:** SaaS dependency and CLI cache semantics after revocation

**Risks:**
- Vendor lock-in mild

**Stepping stone:** yes — opens future possibilities

**Rollback:** Export env to static CI secrets temporarily

### V2. 1Password CLI + Connect or service account

Secret references in templates; op run for processes; GitHub load-secrets-action.

**Strengths:**
- Great if org already on 1Password

**Weakest link:** Connect infra or service account token still a bootstrap; rotation more procedural

**Risks:**
- Connect ops if not using SA token only

**Stepping stone:** yes — opens future possibilities

**Rollback:** Fall back to Doppler or raw secrets

### V3. SOPS + age in repo

Encrypted files in git; decrypt in CI with age key.

**Strengths:**
- No external secret manager SaaS
- Git-native review

**Weakest link:** Rotation and drift management manual; decrypted material on runner disk

**Risks:**
- Key distribution harder for solo

**Rollback:** Stop decrypt step

## Summary

| Variant | Weakest Link | Stepping Stone |
|---------|-------------|----------------|
| V1. Doppler (service tokens + doppler run) | SaaS dependency and CLI cache semantics after revocation | yes |
| V2. 1Password CLI + Connect or service account | Connect infra or service account token still a bootstrap; rotation more procedural | yes |
