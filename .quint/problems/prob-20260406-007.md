# Select Memory pillar for overnight autonomous coding v1

## Signal

The system now has formal decisions for orchestration, DTU, judge, observability, planner, and model/provider, but lacks a formal Memory pillar decision. Current continuity relies on logs/artifacts and ad hoc recall, which risks repeated mistakes, weak cross-run learning, and slower diagnosis in unattended overnight execution.

## Constraints

- Must be self-hostable or local-first for data control
- Must support headless unattended overnight operation
- Must provide durable cross-run memory with explicit retrieval mechanics
- Must be auditable/inspectable by a human reviewer
- Must not create tight lock-in to a proprietary cloud API
- Must integrate with existing Ralph + OpenJudge + Langfuse + Spec Kit workflow with minimal architecture disruption
- Must fit solo-operator operational capacity

## Optimization Targets

- Improve cross-run learning continuity and reduce repeated failures
- Improve retrieval quality for actionable context during overnight execution
- Minimize operational burden while preserving reliability and auditability

## Observation Indicators

- GitHub stars and social trend velocity
- Breadth of optional advanced features beyond pilot/v1 scope
- Novel research claims not yet validated in production settings

## Acceptance

A single memory approach is selected with rationale and fallback. In a controlled trial, memory retrieval improves at least one representative overnight scenario by reducing repeated error loops or setup rework, while keeping operational overhead acceptable and outputs auditable for morning review.

## Blast Radius

Primarily affects planning/execution continuity, diagnostics workflow, and runbook/data management. Other pillars remain functionally intact if memory interfaces stay modular.

**Parity rules:** Use one representative scenario set, one evaluator rubric, and one timebox across variants. Keep orchestrator/planner/model policies unchanged during comparison. Use identical prompts and failure-injection cases where possible. Record unavoidable differences explicitly and normalize scoring rationale.
