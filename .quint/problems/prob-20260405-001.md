# Select overnight orchestration tool (Attractor pillar)

## Signal

Ten orchestration candidates researched; need to select one tool to run an autonomous coding agent loop overnight on a budget VPS. Choice shapes runbook, trace format, and pillar integration patterns. Wrong pick wastes the pilot weekend and creates rework.

## Constraints

- Total monthly spend <$150 AUD (VPS + LLM combined)
- No OpenAI provider dependency (Anthropic, Google, DeepSeek, GLM, OpenRouter all acceptable)
- Must run headless/unattended for up to 10h on a VPS
- Must be BYO-API-key model — no mandatory commercial CLI subscription (Claude Max, Cursor Pro, etc.)
- Must not prevent integration with external Judge, DTU, Leash, and Observability pillars
- Framework/orchestrator itself must be free/OSS

## Optimization Targets

- Overnight reliability (crash recovery, rate-limit resilience, graceful degradation)
- Morning reviewability (structured traces readable by human at 7am)
- Time-to-first-pilot (can run this Saturday night, not in 3 weeks)

## Observation Indicators

- Parallelism capability (not required for vertical slice pilot but watch for v2)
- Community ecosystem velocity (GitHub activity, maintainer responsiveness)
- Context drain resistance over long runs

## Blast Radius

Medium — pilot branch is disposable, but orchestrator choice shapes runbook, trace format, and future pillar integration code. Switching orchestrators later means rewriting integration.

## Reversibility

medium
