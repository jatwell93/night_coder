# Select Observability tool for overnight autonomous coding pipeline

## Signal

The overnight coding loop produces LLM calls, tool invocations, phase transitions, errors, and cost data that nobody monitors in real-time. Morning review currently relies on reading raw orchestrator logs (Ralph events.jsonl) and judge verdicts (OpenJudge JSON). There is no structured trace store, no per-call cost/token visibility, no session-level aggregation, and no UI for browsing execution history. As the system scales beyond the single-file pilot to multi-scenario overnight runs, this gap will make debugging failures, diagnosing cost overruns, and improving agent behavior increasingly difficult.

## Constraints

- Must be self-hostable or run fully local — no mandatory SaaS dependency for trace data
- Must not require the coding agent itself to be modified for basic trace capture (instrumentation should wrap, not invade)
- Must support the already-decided stack: Ralph orchestrator, WireMock DTU, OpenJudge judge
- Pilot infrastructure budget: Hetzner CX22 (2 vCPU, 4 GB RAM) shared with Ralph + WireMock + coding agent
- Monthly LLM cost cap: $50 AUD (observability tool must not consume LLM budget unless explicitly opted in)
- Must preserve prompt/response content for post-hoc review (content tracing on by default)

## Optimization Targets

- Morning review quality: structured, filterable, annotatable trace browsing — not raw log reading
- LLM cost/token visibility: per-call and per-session cost tracking to detect budget drift before it compounds
- Integration effort: minimal setup for pilot, graceful scale-up for production

## Observation Indicators

- Judge pillar overlap: if the observability tool duplicates OpenJudge's eval function, watch for confusion about which judge verdict is authoritative
- Infrastructure resource consumption: RAM/CPU used by the observability stack relative to the agent workload
- Vendor lock-in trajectory: whether the chosen tool's data model makes switching costly later

## Acceptance

1) A human reviewer can browse overnight traces in under 2 minutes, filter by error/cost, and annotate findings. 2) Per-LLM-call token and cost data is visible without manual calculation. 3) The tool runs on the pilot VPS without starving the agent of resources. 4) Post-pilot: the same tool scales to multi-repo, multi-scenario nightly runs without architectural rework.

## Blast Radius

Observability is read-path only — it does not affect agent execution. Choosing wrong means poor morning review (missed bugs, invisible cost drift) but does not break the overnight run itself. Blast radius is moderate: affects debugging velocity and cost governance, not correctness.
