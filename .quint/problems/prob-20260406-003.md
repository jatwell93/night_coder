# Select Judge tool for overnight autonomous coding pilot

## Signal

The overnight coding loop produces execution traces (logs, git diffs, stdout) that need external validation against holdout scenario specs. Without a dedicated Judge component, the coding agent can declare victory without genuine spec satisfaction. A previous informal selection chose OpenJudge but lacked parity comparison, weakest-link analysis, and tracked rationale.

## Constraints

- Python 3.12+ compatible (pip-installable or scriptable)
- Headless CLI invocation — no GUI or web UI required for scoring
- Monthly LLM cost for judge calls under $50 AUD
- No heavy infrastructure (no Postgres, Redis, Celery, K8s required just for judging)
- Must accept arbitrary inputs: scenario markdown text + execution trace text
- Must return structured output: JSON with satisfied (bool), score (0-1), reasoning (string)
- Must support configurable LLM provider — not locked to a single vendor

## Optimization Targets

- Fit-for-purpose: how well the tool maps to 'scenario + trace → satisfaction score' without adaptation overhead
- Integration simplicity: minimal glue code to wire into Ralph orchestrator + Langfuse observability
- Extensibility: ability to add custom graders, rubrics, or function-based scoring beyond the pilot

## Observation Indicators

- Judge latency (scoring is post-run, not in the hot loop — monitor but don't optimize)
- Number of built-in graders (only custom scenario grading needed for pilot — more is nice, not critical)
- Community size / maintenance cadence (watch for abandonment signals)

## Acceptance

A single Judge tool is selected with: (1) Quint DecisionRecord with full rationale, (2) parity-checked comparison across all 4 candidates from Research_Summary_Table.md §1, (3) weakest-link identified, (4) pilot integration path documented. The selected tool can score SCN-PILOT-001 traces within 60 seconds and under $0.10 per invocation.

## Blast Radius

Low. Judge is a post-run scoring step isolated in docs/superpowers/pilot/judge/. Swapping does not affect orchestrator (Ralph), DTU (WireMock), or leash (NTM). Only the judge/ directory and DECISIONS.md row change.
